# Google Sheets refresh through GitHub Actions

This is an alternative to Cloud Run, not a replacement. It uses the same Python
runner and spreadsheet `_config`. Your PC does not need to stay running.
The workflow is manually/API triggered; Apps Script GitHub dispatch is a separate
next step. Keep using the current Apps Script/Cloud Run path until that is added.

The public `edvard-munch/yahoo_roster_scraper` repository can use standard
`ubuntu-latest` runners for free. No larger runner is requested. A private
repository uses the owner's included minute allowance. Check current GitHub usage
and billing settings; setup/install/retries also consume runner time. This workflow
does not upload artifacts or enable a dependency cache.

## 1. Configure Google identity federation

Use a Google Cloud project with Sheets API enabled. Workload Identity Federation
(WIF) and service-account impersonation avoid a downloaded JSON key; Cloud Run,
Cloud Build, Artifact Registry and Secret Manager are not required for this path.
No billable compute resources are created by the following commands. Project
creation/organization policies can still restrict who can configure IAM.

Authenticate `gcloud`, choose your project, and run the **first-time setup** below.
If the pool/provider/service account already exists, inspect/update it rather than
blindly rerunning creation commands.

```bash
export PROJECT_ID="your-google-project-id"
export REPOSITORY="edvard-munch/yahoo_roster_scraper"
export BRANCH="master"
export PROJECT_NUMBER="$(gcloud projects describe "$PROJECT_ID" --format='value(projectNumber)')"
export REPOSITORY_ID="$(gh api "repos/$REPOSITORY" --jq '.id')"
export OWNER_ID="$(gh api "repos/$REPOSITORY" --jq '.owner.id')"
export SERVICE_ACCOUNT="github-roster-scraper@$PROJECT_ID.iam.gserviceaccount.com"
export WORKFLOW_REF="$REPOSITORY/.github/workflows/scrape-google-sheet.yml@refs/heads/$BRANCH"

gcloud services enable --project="$PROJECT_ID" \
  sheets.googleapis.com iam.googleapis.com iamcredentials.googleapis.com sts.googleapis.com

gcloud iam service-accounts create github-roster-scraper --project="$PROJECT_ID" \
  --display-name="GitHub roster scraper"

gcloud iam workload-identity-pools create github-actions --project="$PROJECT_ID" \
  --location=global --display-name="Trusted GitHub workflows"

gcloud iam workload-identity-pools providers create-oidc github \
  --project="$PROJECT_ID" --location=global --workload-identity-pool=github-actions \
  --issuer-uri="https://token.actions.githubusercontent.com" \
  --attribute-mapping="google.subject=assertion.sub,attribute.repository_id=assertion.repository_id" \
  --attribute-condition="assertion.repository_id == '$REPOSITORY_ID' && assertion.repository_owner_id == '$OWNER_ID' && assertion.ref == 'refs/heads/$BRANCH' && assertion.workflow_ref == '$WORKFLOW_REF' && assertion.event_name == 'workflow_dispatch'"

gcloud iam service-accounts add-iam-policy-binding "$SERVICE_ACCOUNT" \
  --project="$PROJECT_ID" --role=roles/iam.workloadIdentityUser \
  --member="principalSet://iam.googleapis.com/projects/$PROJECT_NUMBER/locations/global/workloadIdentityPools/github-actions/attribute.repository_id/$REPOSITORY_ID"
```

Trust is limited to the numeric repository/owner IDs, `master`, this specific
workflow file, and manual/API dispatch. Do not grant access to every repository
or PR workflow. Protect `master` and review workflow/code changes: code on that
branch can act as the Google account during a run. If you rename the repository,
workflow file, or branch, update the Google condition and job branch restriction.
IAM changes may take several minutes to propagate.

Share every target spreadsheet with `$SERVICE_ACCOUNT` as **Editor**. This
spreadsheet sharing permission is separate from IAM. No Drive listing, broad
project Editor role, or service-account key is needed. The Python runner requests
the Sheets scope through ADC, using ephemeral credentials generated by the auth
action.

## 2. Configure the GitHub environment

In the repository, open **Settings → Environments** and create **google-sheets**.
Restrict deployment branches to **master**. Add required reviewers if available
and appropriate (public GitHub Free repositories support environment protection
features; verify your account's UI).

Add these **environment variables**, not credential secrets:

| Name | Value |
|---|---|
| `GCP_WORKLOAD_IDENTITY_PROVIDER` | `projects/PROJECT_NUMBER/locations/global/workloadIdentityPools/github-actions/providers/github` |
| `GCP_SERVICE_ACCOUNT` | `github-roster-scraper@PROJECT_ID.iam.gserviceaccount.com` |

Use the numeric **project number**, not project ID, in the provider path. A review
requirement pauses each run until approved; choose that policy knowing a future
Apps Script button will also have to wait for approval.

No `BACKEND_SECRET` or Google JSON key is needed by this workflow. The later Apps
Script dispatch integration will need a repository-limited GitHub credential;
that is separate from the Google WIF configuration here.

## 3. Publish and run

Commit and push `.github/workflows/scrape-google-sheet.yml` to **master**. GitHub
must see the workflow on its default branch before manual/API dispatch is usable.
Ensure repository Actions settings allow the SHA-pinned actions in the file.

Open **Actions → Refresh Google Sheets stats → Run workflow**. Choose **master**
and supply the spreadsheet ID only, not its URL. The target sheet must already
exist with valid `_config` values (league ID, named season mode, optional ISO date).

Or dispatch from your terminal:

```bash
gh workflow run scrape-google-sheet.yml --repo edvard-munch/yahoo_roster_scraper \
  --ref master -f spreadsheet_id="YOUR_SPREADSHEET_ID"
gh run list --repo edvard-munch/yahoo_roster_scraper --workflow scrape-google-sheet.yml
```

Dispatch does not mean completion. Inspect the Actions run/logs and `_config`:
`running → complete` or `failed`, with `last_run` updated only after success.
Queued runs and authentication/setup failures occur before the Python runner and
therefore do not update `_config` status.

**A run updates real data:** stats ranges are cleared/rewritten and team tabs are
synchronized, including removal of departed teams. Do not use a sheet containing
unrelated tabs you need to keep.

## Execution and safety

- Only `workflow_dispatch` is enabled; no push, schedule, or PR trigger.
- Only `master` runs the job; Google also enforces this restriction.
- Job permissions are limited to `contents: read` and `id-token: write`.
- Third-party actions are pinned to full commit SHAs; review deliberate updates.
- User input is an environment variable, validated before auth, then passed as a
  quoted command argument. It is never interpolated into executable shell source.
- No automatic retries. There is one concurrency group per spreadsheet with
  `cancel-in-progress: false`, so a new dispatch does not cancel an active run.
  GitHub groups are case-insensitive (differently cased IDs may serialize too).
  GitHub can replace an already-pending run with a newer dispatch; avoid repeatedly
  clicking Run. This does not lock against Cloud Run, CLI, or another repository.
- The job timeout is 15 minutes, including setup. Timeout/manual cancellation can
  leave `_config.run_status=running`; confirm the job stopped before clearing stale
  status or retrying. Do not cancel an active run merely to start a new one.
- ADC credential files are temporary, excluded by `.gitignore`, and cleaned up by
  the Google auth action. Do not cache/upload them or log token values.

Yahoo can block GitHub runner IPs even when it works on your PC. Validate one real
run after publishing; mocked local tests do not prove external connectivity or
IAM permission. Check **GitHub Settings → Billing and licensing → usage/budgets**
for actual allowance use. Cloud Run files and the existing Apps Script configuration
remain available for switching hosting paths later.
